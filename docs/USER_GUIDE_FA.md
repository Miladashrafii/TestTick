# راهنمای استفاده از TestTick (فارسی)

آموزش کامل نصب، راه‌اندازی و کار روزمره با TestTick.

English guide: [USER_GUIDE_EN.md](./USER_GUIDE_EN.md)

---

## ۱. TestTick چیست؟

TestTick یک سیستم **مدیریت کیس تست (TMS)** مدرن است که از گردش‌کار کلاسیک TestLink الهام گرفته، با رابط کاربری امروزی و قابلیت‌هایی مثل پیش‌نویس با AI، دریافت نتیجه از CI، تشخیص flaky، کلید API و پشتیبانی کامل **فارسی / RTL**.

مفاهیم اصلی:

| مفهوم | معنی |
|--------|------|
| **پروژه (Project)** | محصول یا سیستمی که تست می‌شود |
| **سوییت / کیس** | مشخصات تست: سوییت‌ها شامل کیس‌ها هستند |
| **پلن (Plan)** | بسته رگرسیون/ریلیز شامل کیس‌های انتخاب‌شده + بیلد و پلتفرم |
| **بیلد (Build)** | نسخه تحت تست (مثلاً `1.0.0-rc1`) |
| **اجرا (Execution)** | ثبت نتیجه Pass / Fail / Blocked / Skipped |
| **نیازمندی (Requirement)** | سند نیازمندی متصل به کیس‌های پوشش‌دهنده |

## ۲. نصب و اجرا

### پیش‌نیاز

- Node.js نسخه ۲۰ یا بالاتر (پیشنهادی)
- npm

### مراحل

```bash
git clone https://github.com/Miladashrafii/TestTick.git
cd TestTick
cp .env.example .env
npm install
npm run db:setup
npm run dev
```

آدرس‌ها:

- فارسی: http://localhost:3000/fa/login  
- انگلیسی: http://localhost:3000/en/login  

### حساب‌های دمو (بعد از seed)

| نقش | ایمیل | رمز |
|------|-------|-----|
| مدیر سیستم | `admin@testtick.app` | `admin123` |
| تستر | `tester@testtick.app` | `tester123` |
| طراح تست | `designer@testtick.app` | `designer123` |

پس از seed یک **API Key نمونه** یک‌بار در ترمینال چاپ می‌شود. برای کلید جدید دوباره `npm run db:seed` بزنید.

### اسکریپت‌های مفید

| دستور | کاربرد |
|--------|--------|
| `npm run dev` | سرور توسعه |
| `npm run build` / `npm start` | بیلد و اجرای پروداکشن |
| `npm run db:push` | اعمال اسکیمای Prisma |
| `npm run db:seed` | بارگذاری داده دمو |
| `npm run db:setup` | push + seed |

## ۳. متغیرهای محیطی

فایل `.env.example` را به `.env` کپی کنید:

| متغیر | ضروری؟ | توضیح |
|--------|--------|--------|
| `DATABASE_URL` | بله | پیش‌فرض SQLite: `file:./dev.db` |
| `AUTH_SECRET` | بله | رشته تصادفی بلند برای Auth.js |
| `AUTH_URL` | بله | آدرس اپ، مثلاً `http://localhost:3000` |
| `OPENAI_API_KEY` | خیر | فعال‌سازی پیش‌نویس کیس با OpenAI |
| `OPENAI_MODEL` | خیر | پیش‌فرض `gpt-4o-mini` |
| `GITHUB_ISSUES_BASE_URL` | خیر | مثلاً `https://github.com/org/repo` برای لینک ساخت Issue |

اگر `OPENAI_API_KEY` نباشد، پیش‌نویس AI با موتور محلی (هیوریستیک) کار می‌کند.

## ۵. گردش‌کار معمول QA

### الف) ساخت یا باز کردن پروژه

1. برو به **پروژه‌ها**.  
2. پروژه را با **نام** و **پیشوند** بساز (برای شناسه کیس مثل `TTS-0001`).  
3. پروژه را باز کن تا داشبورد و منوی پروژه را ببینی.

### ب) نوشتن مشخصات تست

1. **مشخصات تست** (Suites) را باز کن.  
2. سوییت بساز، بعد کیس با این فیلدها:  
   - عنوان، خلاصه، پیش‌شرط  
   - مراحل و نتایج مورد انتظار  
   - اهمیت (بالا / متوسط / پایین)  
   - نوع اجرا (دستی / خودکار)  
3. اختیاری:  
   - **پیش‌نویس AI**: سناریو را بنویس → تولید → ویرایش → ذخیره  
   - **نمای ذخیره‌شده**: فیلترهای جستجو/اهمیت/وضعیت بازبینی  
   - **فیلد سفارشی**: تعریف در تنظیمات، مقداردهی روی کیس  
   - **دیتاست**: ردیف‌های پارامتری برای تست data-driven  

### ج) بازبینی و تأیید

روی کیس یا پلن:

1. **ارسال برای بازبینی**  
2. بازبین **تأیید** یا **رد** می‌کند  
3. جریان وضعیت: `پیش‌نویس` → `در حال بازبینی` → `تأییدشده` / `ردشده`

### د) ساخت پلن تست

1. **پلن‌های تست** → ایجاد پلن  
2. **بیلد** (و در صورت نیاز پلتفرم) اضافه کن  
3. کیس‌های مشخصات را به پلن تخصیص بده

### ه) اجرای تست

1. **اجرا** را باز کن.  
2. پلن / بیلد (و پلتفرم) را انتخاب کن.  
3. نتیجه را با یادداشت ثبت کن: پاس / فیل / بلاک / رد شدن.

**میانبرهای کیبورد** (صفحه اجرا):

| کلید | عمل |
|------|-----|
| `j` / `k` | کیس بعدی / قبلی |
| `p` | پاس |
| `f` | فیل |
| `b` | بلاک |
| `s` | رد شدن |
| `n` | فوکوس روی یادداشت |
| `Enter` | ذخیره نتیجه |

### و) نیازمندی‌ها و پوشش

1. **نیازمندی‌ها** را باز کن.  
2. سند (`REQ-…`) اضافه کن.  
3. کیس‌های پوشش‌دهنده را وصل کن (در گزارش‌ها دیده می‌شود).

### ز) گزارش‌ها و flaky

در **گزارش‌ها** می‌بینی:

- نتایج بر اساس وضعیت  
- کیس‌ها بر اساس اهمیت  
- پوشش نیازمندی  
- نرخ پاس بر اساس بیلد  
- کیس‌های **flaky** (تاریخچه پاس و فیل مخلوط)  
- **رگرسیون** (قبلاً سبز، الان قرمز)

## ۶. قابلیت‌های همکاری

### فعالیت و منشن

- صفحه **فعالیت** پروژه، کامنت‌ها و تغییر وضعیت‌ها را نشان می‌دهد.  
- روی کیس کامنت بگذار؛ اعضا را با `@ایمیل` منشن کن.

### حضور همزمان (Presence)

اگر دیگران در همان پروژه باشند، آواتارشان در هدر دیده می‌شود.

### تست اکتشافی (Exploratory)

1. **Explore** را باز کن.  
2. جلسه با **منشور (charter)** و مدت‌زمان بساز.  
3. حین تایمر یادداشت بردار و در پایان جلسه را ببند.

### لینک به Issue Tracker

از اجرای فیل‌شده یا صفحه کیس:

- لینک به **GitHub**، **Jira**، **Linear** یا URL سفارشی بساز.  
- لینک «ساخت Issue جدید در GitHub» از `GITHUB_ISSUES_BASE_URL` استفاده می‌کند.

## ۷. تنظیمات پروژه

مسیر: **Settings** داخل پروژه.

### کلیدهای API

1. کلید بساز (متن کامل فقط **یک‌بار** نمایش داده می‌شود).  
2. در هدر `Authorization: Bearer <key>` برای REST / CI / GraphQL بفرست.  
3. کلیدهای بلااستفاده را Revoke کن.

### فیلدهای سفارشی

فیلد (متن، عدد، انتخابی، بولین) تعریف کن و روی کیس مقدار بده.

### ورود / خروج داده

خروجی یا ورودی کیس‌ها با فرمت‌های:

- CSV  
- JSON  
- Excel (XLSX)  
- XML شبیه TestLink  

برای مهاجرت از ابزار قدیمی یا اشتراک مشخصات با تیم‌های دیگر مناسب است.

## ۸. استفاده از API

آدرس پایه (لوکال): `http://localhost:3000`

### احراز هویت

- سشن مرورگر (کوکی)، یا  
- `Authorization: Bearer <api-key>`

### REST (نمونه)

```http
GET  /api/v1/projects
GET  /api/v1/projects/{projectId}
GET  /api/v1/projects/{projectId}/cases
POST /api/v1/projects/{projectId}/cases
GET  /api/v1/projects/{projectId}/plans
GET  /api/v1/projects/{projectId}/executions
GET  /api/v1/projects/{projectId}/analytics/flaky
```

### CI — دریافت JUnit

روی کیس‌ها `automationKey` بگذار (یا mapping بساز)، بعد:

```bash
curl -X POST "http://localhost:3000/api/v1/projects/{projectId}/ci/junit?planId=PLAN_ID&buildName=ci-42" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/xml" \
  --data-binary @results.xml
```

نتایج به‌صورت اجرای با منبع `ci` ذخیره می‌شوند.

### GraphQL

آدرس: `POST /api/graphql`  
همان Bearer API Key را بفرست. اسکیما در `src/lib/graphql/schema.ts` است.
